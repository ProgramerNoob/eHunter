# 浏览器验收前置检查与证据保存

## 目标

让 eHunter 的浏览器验收识别错误环境和旧代码，保存可追溯的阶段证据，使准备失败明确阻断后续功能验收。

## 背景与事实

- 用户已审阅最终方案并于 2026-10-12 批准实施，任务已启动。首步能力探针取得 Vite/EH 源码与执行证据；EH 移动严格视口未通过，见[能力报告](research/capability-probe.md)。
- 来源：[复盘第 03 项](../10-11-project-session-retrospective/research/report.md)。历史反例包括旧 bundle、CSS 视口与预期不一致，以及移动模拟与截图记录不匹配。
- 通用浏览器指南与 EH 技能已有服务归属、视口配置、动态 loader、分阶段事件采集及资源清理步骤，本任务补足可执行检查。
- loader 在 eval 前输出“已加载”，不足以证明执行成功；EH 只在阅读器打开时修正移动 viewport，关闭时恢复原站配置。依据与能力限制见 [研究记录](research/browser-preflight-design.md)。

## 需求

- R1：功能验收及阅读器截图前，核对独立预期的 CSS 尺寸、DPR、移动命令回执和实际触摸能力。阅读器正常打开可作为独立准备阶段：打开前先完成代码身份、模拟配置和日志检查，保存原站环境；打开后再检查阅读器实际 CSS 视口。关闭场景检查原站 viewport 恢复，继续验收阅读器时重新打开并检查。不向页面补 meta，不调整预期来迎合实测值。
- R2：确认页面在当前文档实际执行被测代码。EH 比较完整生产包身份及执行证据；Vite 比较本轮实际加载的项目模块清单，并列出未加载模块及独立资源的验证边界。代码或构建在验收中变化使相关证据失效。
- R3：实际生产产物与仓库动态 loader 的 grant 集合相等，loader 的 connect 覆盖生产集合及实际本地 host；单独记录浏览器安装前提，静态检查不声称证明安装副本权限。
- R4：导航、刷新、准备、关键交互及截图的事件按阶段保存；异常和超时仍保存已捕获事件，保存失败不能报告通过。
- R5：准备失败记为 blocked，不进入对应功能回调；进入功能后确认的产品断言失败记为 failed。复用已有逐项验收协议，由主会话回填，不生成手写整体 passed。
- R6：沿用 ego-browser、同一任务空间、服务归属、用户接管与 .tmp/ 产物规则；保留用户资源和存储。正常 UI 准备动作以现有快照或已观察的选择器执行。
- R7：远端更新通知不可用时完成非致命降级，保留失败原因，不产生未处理拒绝或伪造通知成功状态；本地版本说明与正常阅读继续，真实初始化、弹窗和存储异常仍须可见。
- R8：EH 移动阅读器打开时隔离原站超宽内容对布局视口的影响；关闭（含加载错误关闭）恢复原站 viewport 和本次接管的根节点样式；连续开关不得丢失原状态。

## 接受标准

- [AC1] 正确桌面与移动准备产生实际环境记录；错误阅读器 CSS 尺寸、DPR、移动命令或触摸能力阻断功能验收与截图；正常打开的准备阶段与关闭后的原站 viewport 恢复分别留证。
- [AC2] EH 完整生产包及 Vite 本轮已加载项目模块具有当前文档的源码身份和执行证据；旧代码、缺失或历史证据被阻断，未加载模块和独立资源范围明确记录。
- [AC3] 正确仓库 grant/connect 配置通过，缺一项生产权限被阻断，本地 connect 扩展允许存在，静态声明与浏览器安装前提分开记录。
- [AC4] 导航、加载、关键交互及 finally 日志可追溯；异常分支保留先前事件，事件收集或保存失败不得报告通过。
- [AC5] 本地与真实 EH 入口接入同一套准备检查；失败后不执行对应功能回调，逐项报告区分环境阻断、产品失败和未执行。
- [AC6] 所需自动检查、桌面与移动浏览器验证和正式审查完成；交付说明已验证与未验证范围，并按归属清理任务资源。
- [AC7] 更新请求的网络、HTTP、正文、解析和超时失败均保留诊断且不产生严重运行错误、远端弹窗或成功时间写入；本地说明继续。成功通知的语言、版本与时间门槛不变，实际弹窗/存储异常不被吞掉。
- [AC8] EH 移动打开后严格390×844通过，书页/卷轴及关闭重开正常；原站viewport与接管的根节点溢出样式在普通关闭、加载错误关闭和快速重复开关后正确恢复，桌面及非EH不新增该样式接管。

## 边界

2026-10-14 用户同意将更新请求错误和 EH 移动视口不符两个阻塞纳入当前任务。允许在 `src/`、`core/` 中做必要的错误处理与打开/关闭布局修复；原有严格代码身份、日志保存及390×844移动尺寸要求保持。先完成根因复现与方案记录，再实施并回归。

不改变平台解析、存储协议、更新源业务配置或请求层的通用重试契约，不替换浏览器或引入 E2E 框架，不覆盖物理移动设备或其他浏览器，不改远端 CI 与分支保护。正式审查职责调整、待办文档修正、下载 ZIP 内容验证仍留各自后续任务。

## 规划状态

技术方案见 [design.md](design.md)，实施顺序见 [implement.md](implement.md)。CDP 沙箱可见性及执行取证属于实施首步的能力验证；缺少能力时阻断该分支并回到规划，不采用弱证据替代。其余仓库可回答问题已收敛。
